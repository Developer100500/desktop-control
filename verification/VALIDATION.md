# Проверка Desktop Control 0.1.0

Дата: 9 октября 2026. Это рабочая первая версия; полная матрица приёмки на всех конфигурациях ещё не пройдена.

Среда: Windows 10 Pro 22H2, build **19045.6456**, x64; Intel UHD 620, драйвер 31.0.101.2111; один экран 1920×1080, DPI 100%. MSVC 14.51.36231, SDK **10.0.22621.0**, статическая CRT, Release `/O2`. Интерактивные тесты запускались в пользовательском сеансе отдельным нативным клиентом стандартного MCP.

## Непроверенные или недоступные пункты

- Windows 11: нет соответствующей среды. DPI 150/200%, два экрана и отрицательные координаты остаются непроверенными; пользователь отдельно исключил дальнейшие проверки высоких DPI и нескольких мониторов из текущей работы.
- UWP-Калькулятор отсутствует в этом профиле: ни AppsFolder/Get-StartApps, ни установленный Computer Use не находят его. Сценарий 2+3=5 включён в тестовый клиент, но **не выполнен**. Пакеты не устанавливались.
- Пользователь исключил дальнейшие проверки UWP из текущей работы; уже полученные результаты DevToys сохранены, новые проверки UWP не проводились.
- Физическое нажатие Escape человеком, подключение/отключение монитора и аппаратный device removal: не проверены.
- Toggle, SelectionItem, ExpandCollapse, Scroll patterns и Text реализованы; отдельно подтверждены Invoke, Value и чтение Text. Для остальных patterns нужна дополнительная матрица приложений.
- Повторное использование точного значения HWND внутри того же процесса не форсировалось. Регистрация учитывает HWND, PID, создание процесса, UWP-идентичность и события уничтожения окна; нужна отдельная стресс-проверка поколений HWND.
- Окна сохранения, защищённый/заблокированный desktop и отказ фокуса требуют отдельных сценариев. В тестах наблюдался `FOCUS_DENIED` до ввода; сервер не обходил ограничение Windows.
- CMake/Ninja-проект предоставлен. В данной изолированной среде его служебный `cmd.exe`/link-helper зависал при проверке компилятора; сборка подтверждена через `build.ps1 -Direct`, а не через CMake. Это ограничение местной проверки, а не доказательство ошибки проекта CMake.

## Исправления, выявленные тестами

1. Преобразование SoftwareBitmap внутри FrameArrived вызывает прежнюю регрессию; новый движок всегда выполняет его вне callback.
2. На этой Windows 10 `UpdateLayeredWindow` приводил к Win32 error 8 при capture affinity. Постоянная alpha через `SetLayeredWindowAttributes` и обычный WM_PAINT позволяют проверяемый `WDA_EXCLUDEFROMCAPTURE`.
3. UIA может вернуть S_OK с null pattern-интерфейсом; чтение и действия проверяют сам указатель.
4. Быстрые перемещения мыши объединялись Windows и пропускали углы в Paint. `MOUSEEVENTF_MOVE_NOCOALESCE` сохранил штрихи; итоговый домик проверен визуально.
5. Ввод отслеживает только реально вставленные SendInput-события. Ошибка после доставленной части действия возвращает unknown; автоматического повторения нет.

`acceptance/integration.jsonl` содержит неудачный повторный запуск с отказом фокуса; это не скрыто. Успешная проверка Блокнота была выполнена до него и подтверждена сохранёнными свежими PNG/UIA. Отдельные финальные журналы Paint и UWP заканчиваются PASS.

Установленный Computer Use не изменялся. Баг-репорт не отправлялся.
