# Desktop Control plugin

Локальный плагин для прямого управления Windows через существующий MCP-сервер.

## Подключение

Сервер должен находиться в `~/Documents/Codex/desktop-control.exe`. Плагин разрешает этот путь при запуске через Windows PowerShell и `$env:USERPROFILE`, без привязки к имени пользователя. Используется стандартный Windows PowerShell (`powershell.exe`), внешние зависимости не устанавливаются. Потоки MCP передаются через stdin/stdout.

Текущая конфигурация в `mcp.json`; для прежнего формата Codex также включены `.codex-plugin/plugin.json` и `.mcp.json`. Запускать плагин следует в интерактивном сеансе текущего пользователя на разблокированном рабочем столе Windows. После установки проверьте доступность инструментов сервера. Сохранение плагина в аккаунте само по себе не устанавливает локальный сервер и не делает его доступным в браузере или на телефоне.

## Работа

Вызовите skill Desktop Control для задачи в приложении Windows. Он использует begin_task, поиск приложения и окна, свежие observe, одно действие за шаг и end_task. Stop/Escape приостанавливают действия; продолжение требует явного запроса пользователя. После неопределённого результата действие не повторяется автоматически.

Если запрос разрешения пропущен или отклонён, сервер с поддержкой `retry_consent` позволяет повторить его без переподключения: только по явной просьбе пользователя агент вызывает `begin_task` с `retry_consent=true`. Откроется новое окно, которое пользователь должен подтвердить вручную. Без этого параметра следующая попытка вернёт `CONSENT_RETRY_REQUIRED`; истечение времени первого диалога возвращает `CONSENT_TIMEOUT`. Уже выданное разрешение используется до закрытия подключения. После пересборки сервера обновите оба EXE и перезапустите MCP-подключение; старый процесс не получает изменения автоматически.

Это подключение к отдельному MCP-серверу, а не изменение установленного Computer Use.
