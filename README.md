# Desktop Control 0.1.3

Независимый C++23 MCP-сервер управления Windows 10 22H2 / Windows 11, x64. Управляет Win32, UWP и WinRT/WinUI-приложениями с обычными правами пользователя. Не является патчем Computer Use и не использует его внутренний протокол.

## Подключение

1. Скопируйте `desktop-control.exe` и `desktop-control-foreground.exe` из portable-пакета в одну постоянную папку.
2. Подставьте полный путь к нему в `mcp-config.example.json` и добавьте сервер в MCP-клиент, поддерживающий локальный stdio и изображения.
3. Клиент должен запускать процесс **в интерактивном сеансе текущего пользователя**, на разблокированном рабочем столе. Служба Windows/Session 0 или изолированный служебный desktop для этого не подходят.
4. Вызовите `begin_task` с понятным названием. При первой задаче в новом MCP-процессе появится окно «Разрешить на сеанс». Подтверждение действует до закрытия этого соединения, включая новые задачи и смену окон. До разрешения и отображения рамок захват и автоматизация недоступны. После отказа новое окно подтверждения в этом соединении не появляется; для новой попытки нужно переподключение.
5. Найдите приложение через `list_apps` / `list_windows`. Не передавайте HWND: используйте возвращённый `window_id`.
6. Получите `observe`, выполните одно действие и используйте возвращённое свежее наблюдение.

Сервер сам не подключается к модели и не передаёт данные в сеть. Скриншоты и UIA-данные получает вызывающий MCP-клиент; его правила передачи данных определяются этим клиентом.

## Индикация

- Голубые полосы `#4DA6FF`, 3 DIP: каждый подключённый экран.
- Жёлтые полосы `#FFD54F`, 1 DIP: выбранное окно, с учётом его положения в Z-order.
- Панель сверху монитора цели: заголовок, задача, текущий этап и Stop.
- Панель не забирает клавиатурный фокус; полосы пропускают мышь.
- Язык: первый предпочтительный язык интерфейса Windows — русский при `ru`, иначе английский. Для проверки локализации можно передать `--language ru` или `--language en`.
- Overlay-окна имеют `WDA_EXCLUDEFROMCAPTURE`, не входят в каталог целей и не передаются как UIA-элементы выбранного приложения.
- Физический Escape и Stop приостанавливают задачу. Продолжение требует явного `resume`.
- При завершении рамки убираются, панель показывает результат две секунды.

Этапы захвата, преобразования, кодирования, UIA и действий сообщаются самим движком. По умолчанию между вызовами показывается «Ожидание AI-клиента». Сервер **не определяет рассуждение модели по паузе**.

Клиент может сообщить `thinking` или `processing_screenshot` через `report_agent_status`. Для анализа скриншота нужен актуальный `observation_id` изображения. Сообщение действует 30 секунд или до следующей операции.

## Инструменты и минимальный цикл

Пример `tools/call`:

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"begin_task","arguments":{"title":"Заполнить тестовый документ"}}}
```

| Инструмент | Основные аргументы |
|---|---|
| `begin_task` | `title` |
| `end_task`, `list_apps`, `list_windows`, `stop`, `resume`, `diagnostics` | Нет |
| `launch_app` | `app_id`: абсолютный путь `.exe` или AUMID; для Win32 — необязательный массив строк `arguments` |
| `activate_window` | `window_id`, `cursor_fallback=true`; для собственного заголовка: актуальные `observation_id`, `x`, `y`; `foreground_prompt` сохранён как игнорируемый аргумент совместимости |
| `close_window` | `window_id` |
| `observe` | `window_id`; `include_screenshot=true`, `include_text=false`, `backend="auto"` или `"warp"` |
| `element_action` | `window_id`, `observation_id`, `element_id`, `action`; для `set_value` — `value` |
| `click` | `window_id`, `observation_id`, `x`, `y`; `button`, `count=1/2` |
| `scroll` | Те же координаты; `vertical`, `horizontal`: 120 единиц на деление колеса |
| `drag` | `window_id`, `observation_id`, `points=[{"x":10,"y":20},…]`, `duration_ms` ≤ 5000 |
| `press_key` | `window_id`, `key="Ctrl+S"` или `keys=["Ctrl","S"]` |
| `type_text` | `window_id`, `text`: Unicode, максимум 32768 UTF-16 единиц |
| `report_agent_status` | `task_id`, `phase`; для `processing_screenshot` — `observation_id` |

UIA-действия: `invoke`, `set_value`, `toggle`, `select`, `expand`, `collapse`, `scroll`. Для UIA scroll используются значения Windows `ScrollAmount` (0 = большое уменьшение, 1 = малое уменьшение, 2 = нет прокрутки, 3 = большое увеличение, 4 = малое увеличение).

Изображение — MCP content типа `image` с PNG/base64. Метаданные доступны в `structuredContent` и дублируются текстом. `coordinate_mapping_valid` сообщает, можно ли использовать координаты изображения. При несовпадении WGC ContentSize и рамки DWM сервер не угадывает смещение и отклоняет координатное действие.

`blocked_regions` содержит экранные координаты панели: она исключена из изображения, но принимает клики в этой области. Геометрия изображения задана в физических пикселях; преобразование — прибавить `geometry.x/y` к координате изображения. `window_id` связан с HWND, PID, временем создания процесса и идентичностью приложения за UWP-рамкой.

Идентификаторы наблюдений действуют до следующего действия, изменения геометрии или максимум 60 секунд. После UIA worker restart старые ссылки на элементы недействительны. UIA worker хранит последнее UIA-дерево; для переключения между окнами заново вызовите `observe(include_text=true)`.

`outcome` различает:

- `delivered`: действие отправлено; это не гарантия достижения цели приложения.
- `delivered_observation_failed`: действие отправлено, но последующее наблюдение не удалось.
- `rejected`: отказ до выполнения.
- `unknown`: операция могла частично выполниться. **Не повторяйте её автоматически.**

## Сборка

Нужны MSVC x64, Windows SDK **10.0.22621.0 или новее**, CMake/Ninja из Visual Studio; Python нужен только тестам. JSON-библиотека 3.12.0 уже включена с MIT-лицензией и контрольными суммами; загрузки при старте нет.

```powershell
.\build.ps1 -BuildDir C:\work\desktop-control-build
```

Для среды, в которой служебный `cmd.exe` CMake/Ninja не работает, предусмотрена эквивалентная прямая сборка MSVC:

```powershell
.\build.ps1 -BuildDir C:\work\desktop-control-build -Direct
```

MSVC использует `/std:c++latest` для возможностей C++23; CMake задаёт `CXX_STANDARD 23`. CRT статически включена. Manifest задаёт `asInvoker`, `uiAccess=false`, Per-Monitor DPI V2.

## Проверки

`tests/test_protocol.py` проверяет MCP без ввода и без создания активной задачи.

```powershell
python tests\test_protocol.py C:\work\desktop-control-build\desktop-control.exe
C:\work\desktop-control-build\desktop-control.exe --diagnostics
C:\work\desktop-control-build\desktop-control.exe --test-worker-recovery
```

`desktop-control-integration.exe` — нативный тестовый клиент **нашего MCP**, а не протокола Computer Use. Запускайте в интерактивном пользовательском сеансе. Он создаёт собственное тестовое приложение, проверяет PNG, UIA, Unicode-ввод, устаревшие наблюдения, статусы, серии hardware/WARP и остановку перетаскивания. Во время теста видна панель и рамки.

Рядом с интеграционным клиентом можно положить `integration-config.json`:

```json
{"results_dir":"C:\\work\\desktop-control-results","cycles":100,"language":"ru","status_expiry":true,"geometry_test":true}
```

Журнал и изображения тестового приложения сохраняются в этой папке. Для быстрой проверки можно уменьшить `cycles`. При ошибке клиента сервер получает EOF, останавливает управление и закрывает собственные worker.

`geometry_test=true` проверяет перемещение, изменение размера, отклонение старых координат и сворачивание/восстановление собственного fixture. `scenario="indicator_failure"` отдельно проверяет отказ действий после уничтожения полосы индикатора.

`scenario="acceptance"` проверяет Блокнот, установленный UWP-Калькулятор и Paint с собственным BMP. Для Paint клиент сохраняет начальный кадр и ждёт `paint-actions.json` с массивом `strokes` (каждый штрих — массив `{x,y}`). Координаты нужно выбрать по сохранённому кадру. `paint_only=true` пропускает первые два приложения. Отсутствующий Калькулятор отмечается `SKIP`; это не успешная проверка Калькулятора. `scenario="uwp_probe"` проверяет запуск, UIA и PNG установленного DevToys, если он ещё не открыт. Для x86 можно собрать тот же fixture под x86 и указать его имя в `fixture_name`.

## Одно разрешение и активация курсором

Версия 0.1.2 запрашивает разрешение один раз, при первом `begin_task` нового MCP-соединения. Разрешение хранится только в памяти процесса и не переживает переподключение. Оно охватывает снимки окон, UIA, мышь и клавиатуру. Нажатие «Отмена», Escape, Stop, отмена MCP-запроса или разрыв соединения во время подтверждения отменяют начало управления. После отказа сервер не повторяет окно в том же соединении.

`activate_window` сначала вызывает штатный `SetForegroundWindow`. Если Windows отказывает, сервер поднимает выбранное окно без активации, ищет доступную точку с `WM_NCHITTEST=HTCAPTION` и выполняет видимый клик мышью. Перед кликом повторно проверяются идентичность окна, доступность рабочего стола, состояние задачи и принадлежность точки выбранному окну. Кнопки заголовка и перекрывающие окна не выбираются. Не применяются повышение привилегий, AttachThreadInput, синтетический Alt или изменение глобальных настроек блокировки foreground.

Если у приложения нет стандартного заголовка, сервер возвращает `FOCUS_POINT_REQUIRED`. Агент получает новый `observe`, выбирает безопасную точку окна и вызывает:

```json
{"window_id":"WINDOW_ID","observation_id":"FRESH_OBSERVATION_ID","x":120,"y":40}
```

Это аргументы `activate_window`, а координаты относятся к изображению. Для отключения резервного клика предусмотрен `cursor_fallback=false`. `foreground_prompt` принимается для совместимости, но дополнительных окон разрешения не открывает.

Если активация курсором понадобилась во время `click`, `scroll`, `drag`, `press_key` или `type_text`, результат содержит `focus_only=true`, `action_performed=false` и новое наблюдение. Агент анализирует его и следующим вызовом выполняет исходное действие. Это предотвращает ввод по изображению, полученному до активации. Результат `outcome=unknown` по-прежнему запрещает слепое повторение.

### Настройка подтверждений в Codex

Системное окно сервера и подтверждения инструментов в Codex — разные механизмы. Для плагина из личного каталога разрешите его MCP-инструменты в `~/.codex/config.toml`:

```toml
[plugins."desktop-control@created-by-me-remote".mcp_servers."desktop-control"]
default_tools_approval_mode = "approve"
```

Установленный идентификатор локального marketplace может отличаться. Настройка должна относиться только к этому плагину; глобальные разрешения оболочки менять не требуется. Если на отдельных инструментах уже стоит `approval_mode="prompt"`, замените его на `approve` в пределах этого же сервера. Однократное окно сервера продолжает защищать начало управления. Изменение конфигурации требует нового чата или перезапуска приложения.

Регрессионный `scenario="foreground"` проверяет отказ обычной передачи фокуса, резервный клик по заголовку, повторную потерю фокуса без нового запроса, отдельный шаг активации перед вводом, Unicode readback, повторное использование разрешения между задачами и отказ от разрешения без повторного запроса. Первое подтверждение в тесте симулируется тестовым клиентом только для своего MCP-процесса; это не проверка физического клика человека.

Нативный API `include/foreground_permission.hpp` и CLI `desktop-control-foreground.exe --grant SERVER_PID SERVER_PROCESS_CREATED` сохранены для клиентов, которым нужна штатная передача `AllowSetForegroundWindow`; обычному агенту они больше не требуются при каждой активации.

## Ограничения

- Работа только на активном default desktop. Недоступный/заблокированный рабочий стол и повышенные приложения отклоняются.
- Фокус устанавливается штатным API с резервной активацией мышью. Если ни заголовок, ни явно выбранная наблюдаемая точка не доступны, действие возвращает конкретную ошибку. Ограничения защищённого desktop и UIPI сохраняются.
- Свёрнутые окна для захвата и ввода не поддерживаются; восстановление выполняет пользователь.
- Защищённое содержимое может быть недоступно WGC. Чёрное изображение само по себе не позволяет достоверно определить причину.
- SDR; HDR выдаёт отдельную ошибку.
- Дерево UIA зависит от приложения. Canvas и некоторые custom-контролы требуют визуального анализа внешней моделью.
- Без отдельного адаптера клиента модельные статусы доступны только при явном `report_agent_status`.
- Кнопка Stop и Escape доступны, пока Windows доставляет события нашему пользовательскому процессу; защищённый desktop исключён.

## Устройство исходников

- `src/server.cpp`: MCP, координация и проверка аргументов.
- `src/indicator.cpp`: полосы, панель, DPI, локальная остановка.
- `src/capture.cpp`, `src/uia.cpp`: изолированные worker.
- `src/desktop.cpp`: приложения, цели, координаты и ввод.
- `src/foreground.cpp`, `src/foreground_helper.cpp`: передача разрешения на фокус и изолированный помощник.
- `src/common.cpp`: RAII, локализация, обмен с worker и таймауты.
- `resources/strings.hpp`: компилируемые английские и русские строки интерфейса.

Portable-пакет содержит `diagnose.ps1`: он выводит JSON состояния; `-WorkerRecovery` дополнительно проверяет остановку и восстановление зависших worker (примерно 15 секунд).

Windows-компоненты не устанавливаются и не изменяются. Код плагина Computer Use, драйверы и службы не затрагиваются.

## Общий таймаут CLI

```powershell
desktop-control.exe --timeout 300
desktop-control.exe --timeout 300 --language ru --diagnostics
```

`--timeout SECONDS` принимает целое число секунд от 1 до 86400. Он заменяет таймауты ожидания worker, кадра, обхода UIA, появления окна приложения, поиска точки заголовка, появления индикатора и разрешения сеанса. Срок действия `observation_id` получает то же значение: `--timeout 300` оставляет агенту до пяти минут для анализа наблюдения перед следующим действием.

Без параметра сохраняются прежние значения: worker 5 с, кадр 2 с, обход UIA 3 с, запуск 15 с, разрешение сеанса 45 с, наблюдение 60 с. Это общий настраиваемый бюджет перечисленных ожиданий, а не жёсткий дедлайн всей цепочки: составной вызов может выполнять несколько этапов.

`diagnostics` / `--diagnostics` показывает эффективные значения в `timeouts`. Проверки геометрии и устаревания после действий сохраняются. Stop/Escape и отмена MCP остаются действующими.

Длительность drag (до 5000 мс), краткие проверки фокуса, опрос отмены, освобождение ресурсов и срок отображения статуса агента не увеличиваются: это отдельные ограничения ввода и механизмы отзывчивости.

В конфигурации MCP-клиента добавьте `"--timeout", "300"` в `args` команды запуска EXE. См. `mcp-config.timeout.example.json`. Его собственный таймаут MCP-вызова настраивается отдельно; сервер не может увеличить его своим CLI-параметром.
